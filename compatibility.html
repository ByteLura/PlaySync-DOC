Compatibility & Honest Limits

What PlaySync Pro runs on, and — stated plainly — what it does not do. Everything on this page comes from the product's own compatibility specifications and guides.

Honest limits

  • It is an editor tool, not a save system. PlaySync Pro's tools run exclusively in the Unity Editor — they persist Play Mode tweaks into your scene during development. This is not a runtime save-game system for players. What reaches a build is limited to the [AutoSavePlayMode] attribute and the preset containers, which compile cleanly with zero overhead.
  • The restore popup is conditional. The Quick Restore Window only triggers when active serialized changes were detected during playback. If nothing changed, nothing appears. If it should have appeared, check that "Auto-Open Restore Window" is enabled in Auto-Save Settings.
  • History is local and finite. The Flight Recorder keeps the previous 25 sessions, stored as JSON in [Project]/Library/PlaySyncHistory/ on your machine only. It is a working safety net, not an archive — and because it lives in Library/, it is never committed to your repository.
  • Prefab restores go to the instance. Restoring a prefab instance's tweaks writes to the scene instance without breaking the prefab link. Applying those overrides to the source prefab asset itself is done with Unity's standard Inspector controls, not by PlaySync.
  • Live polling is off unless you turn it on. Since release 1.0.1, live background polling in Play Mode is opt-in and off by default. On very large projects, narrowing the Tracking Scope (Active Selection Only, or Marked Attributes Only) is the documented way to keep tracking overhead at zero.
  • What gets tracked is serialized state. The diff covers Transforms, colliders, lights, cameras, audio, and serialized MonoBehaviour fields. Changes with no serialized representation have nothing to stage.

What changed in 1.0.1

Release 1.0.1 is a performance and control patch: it removed a slow global-ID lookup from Inspector and repaint loops (editor GUI overhead dropped from over 25 ms to under 0.001 ms), removed a project-wide ScriptableObject scan that could freeze scene transitions in massive projects, added the three Tracking Scopes, added master toggles for the Inspector banner, hierarchy highlights, SceneView HUD, and live polling, and made polling opt-in. The full release history is on the Support page.
